Задача — спроектировать и реализовать 
платформу для одиночной игры в D&D 5e, где роль Мастера (DM) исполняет 
локальная LLM, запущенная через koboldcpp. Ниже — полное ТЗ. Следуй ему 
буквально, не додумывай лишнего. Если что-то неясно — задай уточняющие 
вопросы перед началом.

═══════════════════════════════════════════════════════════════
1. ГЛАВНАЯ ЦЕЛЬ
═══════════════════════════════════════════════════════════════
Десктопное приложение (Windows приоритет) для соло-игры в D&D 5e. 
LLM отвечает ТОЛЬКО за нарратив, диалоги NPC и описание мира. Вся 
механика (HP, статы, инвентарь, броски, квесты, заклинания, состояния) 
считается программно движком. LLM НЕ имеет права менять числа напрямую 
— только запрашивать изменения через структурированный JSON, который 
валидируется движком.

═══════════════════════════════════════════════════════════════
2. ТЕХНОЛОГИЧЕСКИЙ СТЕК
═══════════════════════════════════════════════════════════════
- Backend: Python 3.11+ + FastAPI
- Frontend: Electron + React (или Tauri + React)
- БД: SQLite (сохранения, кэш переводов, кэш правил)
- LLM-сервер: koboldcpp (OpenAI-совместимый эндпоинт /v1/chat/completions)
- Парсинг PDF: PyPDF2 / pdfplumber / pypdf
- RAG: ChromaDB + embeddings (sentence-transformers)
- Перевод: googletrans (с fallback на deep-translator)
- Парсер правил: Selenium + BeautifulSoup (совместим с Pars_DnD)

Всё работает оффлайн. Интернет нужен только для:
  - синхронизации правил с dnd.su (по кнопке)
  - Google Translate (перевод чата)

═══════════════════════════════════════════════════════════════
3. АРХИТЕКТУРА
═══════════════════════════════════════════════════════════════
Frontend (UI) ──► Backend (FastAPI) ──► koboldcpp (LLM)
                      │
                      ├── State Manager   (единый источник правды)
                      ├── Rules Engine    (D&D 5e механика)
                      ├── Dice Roller
                      ├── PDF Parser      (лист персонажа + кампания)
                      ├── RAG             (поиск по кампании)
                      ├── Translator      (RU↔EN + кэш)
                      ├── Prompt Builder
                      └── Save/Load

Ключевой принцип: State Manager — единственный модуль, который 
изменяет состояние персонажа. LLM может только ВЫДАВАТЬ запросы 
на изменение, движок их валидирует и применяет.

═══════════════════════════════════════════════════════════════
4. ЯЗЫКОВАЯ СХЕМА (КРИТИЧНО!)
═══════════════════════════════════════════════════════════════
Интерфейс полностью на РУССКОМ. НО:

  Игрок (RU) → [перевод RU→EN] → LLM (EN) → [перевод EN→RU] → Игрок (RU)

- Сообщения игрока: RU → EN через Google Translate
- Системный промпт: только EN (зашит в программу)
- Блок state (JSON с числами): без перевода
- narrative ответа LLM: EN → RU
- suggested_actions: EN → RU
- Формулы бросков: без перевода
- PDF кампании: если на русском — перевести чанки ОДИН РАЗ при 
  загрузке в RAG, хранить англ. версию
- ОБЯЗАТЕЛЬНО: кэш переводов в SQLite (хэш текста → перевод), 
  иначе Google заблокирует по лимиту

Google Translate использовать через библиотеку googletrans (без API-ключа).
Обязательно: retry с exponential backoff, fallback на deep-translator.

═══════════════════════════════════════════════════════════════
5. ФУНКЦИОНАЛЬНЫЕ МОДУЛИ
═══════════════════════════════════════════════════════════════

5.1. State Manager
Хранит: Character (имя, раса, класс, уровень, STR/DEX/CON/INT/WIS/CHA, 
модификаторы, proficiency, HP max/current/temp, AC, инициатива, скорость, 
hit dice, death saves, состояния), Inventory, Spellbook (ячейки по 
уровням, концентрация), Quest Log, NPC/фракции, World State (локация, 
время, погода, флаги), Combat State (без сетки — только текстовые теги 
позиций: "ближний бой", "дальний бой", "укрытие", "вне зоны").

5.2. Rules Engine (D&D 5e)
- Модификаторы, proficiency, преимущества/помехи
- Атаки, урон, спасброски, проверки навыков, инициатива
- Сопротивления/иммунитеты к урону
- Условия (conditions) и длительность
- Ячейки заклинаний, короткий/длинный отдых
- Level up
- Смертельные спасброски

5.3. Dice Roller
Парсер формул: 2d6+3, 1d20+5 adv, 4d6dl1, 1d20+5 dis.
Логирование всех бросков.

5.4. PDF Parser
Два типа PDF:
  A) Лист персонажа — парсинг в структуру Character.
     MVP: ручное сопоставление полей (форма с превью).
     V2: чтение fillable PDF по именам полей.
     V3: OCR + LLM-extraction.
  B) Модуль/кампания — извлечение текста, чанкинг, embeddings, 
     загрузка в ChromaDB. Отдельно хранить DM-only секреты 
     (то, что игрок не должен видеть).

5.5. Prompt Builder
Формирует запрос к LLM полностью на английском:
- system: роль DM, правила, формат ответа
- state: JSON с актуальным состоянием (только релевантное)
- rag_context: релевантные чанки кампании (top-K из ChromaDB)
- history: последние N сообщений (с суммаризацией старых)
- response_format: инструкция вернуть строгий JSON

5.6. Протокол ответа LLM (жёсткий JSON)
{
  "narrative": "текст для игрока (на английском)",
  "requested_checks": [
    {"type":"skill","name":"Perception","dc":15,"reason":"..."}
  ],
  "state_changes": [
    {"op":"add_item","target":"player","item":"Rope","qty":1},
    {"op":"damage","target":"player","amount":"2d6","type":"fire"},
    {"op":"set_flag","key":"found_secret_door","value":true}
  ],
  "suggested_actions": ["осмотреть стол", "поговорить с NPC"]
}

Использовать GBNF-грамматику koboldcpp для гарантии формата.
Backend валидирует state_changes (нельзя получить предмет, которого 
нет в мире; нельзя нанести урон без триггера). Невалидный JSON → 
retry (max 2) → fallback-сообщение игроку.

5.7. Game Loop
1. Игрок пишет действие (RU)
2. Перевод RU→EN
3. Prompt Builder собирает контекст
4. Запрос в koboldcpp
5. Парсинг ответа (GBNF гарантирует JSON)
6. Валидация и применение state_changes через State Manager
7. Перевод narrative и suggested_actions EN→RU
8. Рендер в UI + обновление панелей

5.8. UI (полностью на русском)
- Чат (основной поток, механика сворачиваемая)
- Панель персонажа (HP, AC, слоты, состояния — всегда видна)
- Инвентарь (drag&drop, экипировка, вес)
- Журнал квестов
- Настройки (endpoint koboldcpp, модель, temperature, context size, 
  выбор редакции правил 5e/5.5e)
- Кнопки сохранения/загрузки, undo последнего хода

═══════════════════════════════════════════════════════════════
6. ПРАВИЛА D&D
═══════════════════════════════════════════════════════════════
Источник: dnd.su. У сайта НЕТ публичного API — использовать 
open-source парсер Pars_DnD (Python + Selenium) для сбора JSON 
по классам, расам, заклинаниям, бестиарию.

Локальный кэш:
data/rules/
├── 5e_2014/{classes,races,spells,bestiary}/
└── 5.5e_2024/{classes,races,spells,bestiary}/

Синхронизация — по кнопке "Обновить правила" в настройках.
Rules Engine и Prompt Builder берут данные ТОЛЬКО из локального кэша, 
не парсят сайт на каждом ходу.

При старте игры — выбор редакции (5e / 5.5e).

═══════════════════════════════════════════════════════════════
7. МОДЕЛЬ LLM
═══════════════════════════════════════════════════════════════
Основная: RPBizkitRemiX-v3-12B.i1-Q5_K_M (GGUF)
  - Mistral Nemo 12B, 128K контекста
  - RP-ориентированная, uncensored
  - Шаблон промпта: Alpaca (RAW inputs)
  - Temperature: 0.86–0.92

Альтернатива: MN-Violet-Lotus-12B.Q5_K_M
  - Хороший сторителлинг, но обычная версия страдает от 
    "lost in the middle" на длинном контексте
  - AttnRes-версия не работает в koboldcpp — не использовать

Если модель на 12B и контекст < 32K — ОБЯЗАТЕЛЬНО внедрить 
суммаризацию: каждые 15-20 ходов отдельный вызов LLM "сожми 
последние N сообщений в 5 предложений", заменить старое.

═══════════════════════════════════════════════════════════════
8. РЕЖИМ БОЯ
═══════════════════════════════════════════════════════════════
БЕЗ боевой сетки (слишком сложно для LLM). Theater of the Mind:
- Позиции абстрактные: "ближний бой", "дальний бой", "укрытие"
- В system prompt жёстко прописано: "Do not use coordinates or grid. 
  Track positions abstractly. If player's action requires precise 
  positioning, ask clarifying question in narrative."
- Rules Engine всё равно считает инициативу, HP, урон, условия
- UI показывает порядок хода списком, не на карте

═══════════════════════════════════════════════════════════════
9. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
═══════════════════════════════════════════════════════════════
- Полностью оффлайн (кроме dnd.su sync и Google Translate)
- Автосейв после каждого хода
- Undo последнего хода (снапшот состояния)
- Логирование всех запросов к LLM, ответов, изменений состояния
- Отклик UI < 100 мс

═══════════════════════════════════════════════════════════════
10. ПЛАН РЕАЛИЗАЦИИ
═══════════════════════════════════════════════════════════════

MVP (первая рабочая версия):
- Ручной ввод листа персонажа (форма)
- Чат с LLM, системный промпт с полным state в каждом запросе
- Парсинг JSON-ответа, применение narrative + state_changes
- Автообновление HP, инвентаря, слотов
- Dice Roller
- Save/Load
- Перевод RU↔EN через googletrans + кэш
- Загрузка PDF кампании → текст в контекст (без RAG, обрезка)

V2:
- PDF-парсер листа персонажа (fillable forms)
- RAG по кампании (ChromaDB + embeddings)
- Полный Rules Engine (боевая система)
- Level up
- Парсер правил с dnd.su

V3:
- OCR + LLM-extraction для любых PDF
- Голосовой ввод/вывод
- Мультиагентность (отдельный "правиловой" агент валидирует DM)
